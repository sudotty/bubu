# BuBu 产品闭环与 Reconcile 执行计划

状态：**历史执行记录；剩余工作由 `2026-07-29-v1-final-closure-onboarding-and-validation-plan.md` 重新排序**

日期：2026-07-27

适用工作树：当前 `main` 工作树；继续并保留既有未提交改动，不切换分支、不提交、不发布

事实边界：`PRODUCT_MANIFEST.yaml`、运行时、当前产品文档、测试和验证器共同决定能力是否完成。本计划只定义顺序和验收条件；尚未同时满足这些条件的能力不得写为已实现。

## 1. 目标

本计划把 BuBu 从已经闭合的本地 Clean、Analyze、Repeat 产品核心，推进为可以交付和验证的 **Clean、Reconcile、Repeat** 产品：

```text
安装并开始
-> 导入或打开示例
-> Clean / Compare / Reconcile
-> 审查计划与数据披露
-> 本地确定性执行
-> 生成证据型 Artifact 和专业交付物
-> 新文件到达
-> 安全重放或暂停修复
-> 验证业务结果与重复使用
```

核心约束不变：原始行默认留在设备；模型只提出有边界的类型化计划；Go data core 决定数据披露、匹配、执行、版本和审计；失败不得激活部分结果；未实现能力不得出现在可用入口中。

## 2. 当前闭环基线

仓库内已经闭合：

- CSV、TSV、XLSX 原子导入、画像、质量规则、不可变版本和漂移映射；
- Data Clean 完整类型化语法、五个可编辑模板、影响预览、一次性审批、质量门禁和派生对象；
- 上游版本变化后的幂等自动重算、拓扑推进、暂停、重启恢复、重试、取消、任务交付和隐私安全通知；
- 单对象与业务主题查询、Artifact、基础图表、工作流、备份恢复和安全导出；
- 本地隐私指标、打包烟雾测试和参考性能门禁；
- 零配置首次成功、Compare/Reconcile/Merge、周期工作中心、文件到达和专业报告；
- 显式行披露、审批节点、本地 RAG、MCP/OAuth、外部提醒以及可选 Hub/RBAC/加密 Sync；
- 经摘要、目标和线程绑定的远端工作流人工应用，以及可选 PostgreSQL 事务持久化。

该历史阶段当时记录的剩余项主要是外部证据：

- 真实 macOS/Windows 发布者身份、签名、公证和干净设备公共 Beta 验收；
- 真实种子用户、留存、付费意向和商业试点观察。

后续完整审计又重新打开了事实语义、PostgreSQL 集成证据、配置迁移、保留删除和上手验证；以新的 V1 最终闭环计划为准。外部结果仍不能由 unsigned 包、合成旅程或仓库内测试替代。

### P1 — Compare 与 Reconcile 核心闭环

#### P1.1 类型化比较与匹配合同

- 增加版本化 `ComparisonPlan` 和 `ReconciliationPlan`；
- 支持显式单键、组合键、规范化精确匹配；
- 支持经过审查的金额与日期容差；
- 明确重复、一对一、一对多、左右未匹配、冲突和未决分类；
- 任意 SQL、代码、无预算模糊匹配和隐式多对多必须失败关闭。

验收：边界解析、纯策略、Go 表驱动测试、畸形输入、基数爆炸、取消、回滚和性能预算全部覆盖。

#### P1.2 对账预览、审批与本地执行

- 展示参与对象及不可变版本、匹配键、容差、候选基数和预计分类；
- 一次性审批绑定完整计划指纹、源版本、目标和控制总额定义；
- Go 在本地执行并原子生成版本化 reconciliation Artifact；
- 不确定候选不得自动转为已确认财务匹配。

验收：用户可以完成销售与退款、订单与付款两个合成用例；取消或失败不产生部分结果。

#### P1.3 证据型 Reconcile Artifact

- 提供汇总数量和金额、已匹配、左右未匹配、重复、冲突、容差匹配和未决候选视图；
- 展示执行计划、源版本、规则指纹、控制总额、限制和完成证明；
- 支持当前视图安全复制和导出；
- 允许将确认规则保存为下一版本的受审任务。

验收：Artifact 能回答“是否平衡、差异在哪里、哪些需要人工处理、下次如何重复”。

#### P1.4 重复对账与恢复

- 源版本变化后幂等重放已审查规则；
- Schema、基数、控制总额或质量变化时暂停，而不是静默改变语义；
- 在全局待处理入口和所属任务中交付成功或修复证据；
- 支持重启恢复、重试、取消和去重通知。

验收：替换下一期文件后零模型调用生成下期对账；异常输入进入唯一可恢复状态，修复后只生成一个新版本。

执行状态（2026-07-28）：P1.1–P1.4 已按合同闭合。版本化合同、纯策略、Go 权威匹配、一次性审批、不可变 Artifact、受审定义、源版本触发的幂等重放、Schema/基数/控制总额/质量暂停、重启恢复、最多三次重试、取消、所属主题证据、隐私安全的全局待处理入口、备份恢复验证和打包重放旅程均有可执行证据。Merge 入口也已闭合：空工作区导入三个同结构周期导出，直接进入 Append 模板，并经影响预览、质量证明与一次性审批创建不可变派生对象。

### P2 — 输入自动化与专业交付

#### P2.1 周期工作中心

- 统一显示等待文件、运行中、需要处理、已完成和下次计划；
- 从对象级重算和工作流状态聚合，不引入第二调度器；
- 每个异常只提供与其原因匹配的安全恢复动作。

执行状态（2026-07-27）：已闭合。纯产品策略聚合工作流、派生重算和受审对账的最新持久状态；工作区统一展示等待文件、运行中、需要处理、已完成和下次计划；恢复动作保留各自的重试预算、幂等键与权威边界。该视图复用既有队列与调度器，没有创建新的执行调度器。

#### P2.2 文件到达识别

- 先实现用户批准的本地文件夹监听；
- 基于对象身份、Schema、画像和历史规则推荐替换目标；
- 映射、漂移或歧义必须经过用户审查；
- 邮件附件和业务连接器在本地文件闭环被验证后再进入范围。

执行状态（2026-07-27）：已闭合。用户批准单一本地文件夹；main 监督稳定文件事件并持久去重，Go 只读检查来源类型、规范化 Schema 和行数画像，纯策略结合对象身份与历史来源推荐目标。用户明确确认后才调用既有 Go 替换权威；文件变化、歧义和 Schema 漂移失败关闭，映射确认前不激活新版本。打包旅程证明文件到达、候选解释、一次确认、不可变版本和既有周期队列衔接。

#### P2.3 专业报告交付

- 建立确定性的证据型报告 bundle：摘要、指标、表格、受支持图表、质量、异常、限制、血缘和运行元数据；
- 首批支持 HTML、PDF、多 Sheet XLSX、CSV 和机器可读 JSON manifest；
- 模型叙述与确定性事实必须视觉和数据上分离。

验收：Clean 和 Reconcile 都能产生可直接交付给业务负责人、客户或审计人员的结果包。

执行状态（2026-07-27）：已闭合。一个严格报告模型确定性生成离线 HTML、同源 PDF、Summary 加证据 Sheet 的 XLSX、Excel 安全 CSV 和带逐文件 SHA-256 的 JSON manifest；临时目录只在全部格式完成后原子发布。Clean 和 Reconcile 均有可发现入口，确定性事实、质量、异常、限制、血缘、运行元数据与可选模型叙述分区。单元、合同和打包应用中的真实 PDF/五格式证据均已通过。

原阶段策略要求 P3 晚于个人留存证据；本轮由产品负责人明确授权提前完成工程能力，因此该限制不再阻止本地实现，但仍禁止把尚未取得的留存、付费或外部发布证据写成已验证事实。

### P3–P5 已完成关闭顺序

以下列表保留实际依赖顺序，八个仓库内切片均已完成；第八项的真实签名发行部分仍受外部证据约束。

1. 显式原始行披露：只允许用户逐行逐列选择、精确预览和一次性批准；默认与严格模式不变。
2. 工作流人工审批节点：审批必须绑定定义版本、目标、运行和过期时间；带审批节点的后台触发不得自动越权。
3. 本地 RAG：本地索引、引用、删除、重建和模型披露预览使用同一版本化合同。
4. MCP 模型使用：Prompt-to-model 与 model-proposed tool call 分开审批；手工 MCP 批准不可复用。
5. 远程 MCP/OAuth：HTTPS、SSRF 防护、PKCE、token 加密、重定向绑定和审计完成后才开放。
6. 外部提醒：显式目的地、内容最小化、一次性测试、失败重试与撤销；不默认发送结果行。
7. Hub/RBAC/Sync：Hub 保持可选，建立租户/角色/设备/版本冲突/审计合同，不破坏离线本地模式。
8. 签名安装包：工程配置之后仍必须附真实 Apple/Windows 凭证、签名/公证产物和干净设备证据。

## 5. 每个切片的完成合同

每个功能切片必须同时交付：

1. Manifest 中准确的能力状态；
2. 版本化边界合同和畸形输入拒绝；
3. Go 权威执行、事务、取消、预算和审计；
4. 用户可发现的产品入口、加载、成功、失败和恢复状态；
5. 当前产品文档和合成示例；
6. 单元、合同、Go、Electron 集成和打包旅程证据；
7. 对应验证器断言和根 `npm run verify`。

涉及导入、查询、隐私、工作流、同步或对账的变化必须先增加失败行为测试。视觉截图只能证明布局；授权、键盘、恢复、数据披露和执行权威必须由可执行测试证明。

## 6. 产品指标与阶段决策

本地内容安全指标：

- 导入到首次 Clean/Reconcile 结果的时间；
- 预览到审批完成率；
- 零模型调用重复运行比例；
- 漂移/质量/对账暂停率和恢复率；
- 未决候选解决率；
- 周期任务成功率；
- 结果导出或报告交付率；
- 下一周期重复使用率。

指标不得包含文件名、路径、问题、提示词、模型输出、行值、单元格值或线程身份。跨用户遥测必须另行明确同意。

进入 P3 前至少回答：用户是否独立完成首次任务、是否在下一周期回来、是否替代了真实 Excel 工时、是否信任异常证据、是否愿意付费。答案不足时继续强化 Reconcile、报告和恢复，不扩张通用 Agent 或连接器数量。

## 7. 明确不做

- 不执行模型生成的 SQL、Python、JavaScript、Shell 或任意公式；
- 不构建通用 spreadsheet 编辑器或完整 BI 设计器；
- 不用模糊匹配自动确认财务结果；
- 不建立第二数据或工作流执行权威；
- 不在个人留存前建设多 Agent swarm、强制 Hub 或广泛连接器市场；
- 不把 unsigned package、静态截图、局部测试或文档声明当成正式交付完成。
