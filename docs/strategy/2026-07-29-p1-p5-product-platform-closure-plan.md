## 1. 目标与产品边界

P1–P5 的目标不是堆积功能，而是把同一个可证明系统扩展成完整产品平台：

```text
用户意图
-> 纯策略生成有限状态与风险
-> 版本化合同跨越进程边界
-> 用户审查精确计划、数据与目的地
-> Go data core 决定本地数据、事务、版本、重放和审计
-> Electron main 只监督进程、凭证和操作系统能力
-> Renderer 只呈现状态并发出命名请求
-> Artifact、血缘和追加式账本证明发生了什么
```

必须保持：本地模式不依赖 Hub；远程模型默认零原始行；严格模式不可被临时批准绕过；模型、MCP 和远程服务不能执行任意 SQL、代码或 Shell；失败不得激活部分结果。

## 2. 多模块共生架构

| 模块 | 唯一职责 | 明确不拥有 |
| --- | --- | --- |
| `packages/contracts` | 版本化消息、解析器、预算和状态机形状 | I/O、凭证、数据库 |
| `packages/product-core` | 纯策略、规范化、风险、审批摘要和合并决策 | 时间、网络、文件、浏览器 API |
| `services/data-core` | 原始行、SQLite、索引、执行、版本、事务、审计和同步冲突权威 | 模型协议、桌面 UI |
| `services/ai-runtime` | 模型与 MCP 协议适配、流式响应、严格输出解析 | 数据库权威、用户审批 |
| `apps/desktop/src/main` | 进程监督、系统凭证、通知、一次性会话和命名 IPC | 业务规则、任意数据执行 |
| `apps/desktop/src/renderer` | 可发现入口、精确预览、审批、结果与恢复 UI | Node、IPC 通道、原始文件、凭证 |
| `services/hub` | 可选租户协作、策略分发和加密同步中继 | 本地启动依赖、本地数据权威 |

共享抽象只有在至少两个真实消费者出现时才提取；每个功能先形成窄垂直切片，禁止建立抽象框架后再寻找用途。

## 3. 执行阶段

### P1 — Clean / Compare / Reconcile 确定性核心

状态：**已完成并作为回归基线保留**。

- 类型化 Clean、Compare、Reconcile 与 Merge 计划；
- Go 权威预览、一次性审批、原子物化、证据 Artifact；
- 源版本触发的幂等重放、暂停、恢复、重试、取消和备份验证。

回归要求：任何 P3–P5 改动都不得改变受审计划指纹、控制总额、原子激活或零模型重放语义。

### P2 — 周期输入与专业交付

状态：**已完成并作为产品旅程基线保留**。

- 周期工作中心、本地文件到达审查；
- Clean/Reconcile 专业 HTML、PDF、XLSX、CSV、JSON manifest bundle；
- 打包应用中的首次成功、重复作业和恢复证据。

### P3.1 — 显式原始行披露

1. 先写失败合同：只接受一个数据版本、显式列集合、显式行索引、用途、目的地和固定预算；拒绝通配、范围扩张、陈旧版本与空选择。
2. Go 生成精确只读预览和内容摘要；预览不得由 renderer 自行拼装。
3. 一次性审批绑定数据集/版本、列、行、顺序、目的地、用途、payload 摘要和十分钟过期时间。
4. 严格模式永远拒绝；本地模型仍需显式批准；远程调用前 DLP 再检查并写追加式披露账本。
5. UI 逐列逐行选择，明确显示真实单元格数、字节预算、目的地和不可撤回提示；取消不产生模型调用。
6. 打包旅程证明默认零行、精确批准、一次消费、过期/版本变化失败关闭。

### P3.2 — 工作流人工审批节点与安全恢复

1. 增加版本化 `human-approval` 节点和纯状态机；审批绑定工作流定义版本、运行、节点、目标、风险、过期时间。
2. 后台触发到达审批节点必须暂停并生成唯一待处理事项，不能继承交互式或旧运行批准。
3. 批准后从下一安全检查点继续；拒绝、撤销、过期和重启均保留终态证据。
4. 外部、破坏性、付费、披露和共享副作用以后只能挂在该节点之后。

### P3.3 — 本地 RAG、引用与业务语义记忆

状态：**已完成（2026-07-29）**。首版以可解释 SQLite FTS 和版本化本地文档为边界；OCR、Embedding、跨来源模型回答和工作流知识节点仍是后续独立能力。

1. 版本化文档来源、切片、索引、引用和披露预览合同；限制文件类型、大小、条目数和总字节。
2. Go 持有文本、索引、删除、重建与版本；首版使用可解释的 SQLite FTS/词项评分，不引入第二数据库。
3. 检索结果必须带来源版本、片段定位和得分；回答只能引用已披露片段。
4. 送入远程模型前复用隐私策略、DLP、一次性审批和模型账本；删除来源必须删除索引并使旧引用失效。
5. 工作区提供“业务知识”入口、索引健康、重建、删除、引用跳转和精确披露预览。

### P4.1 — MCP Prompt-to-model 与 model-proposed tool call

状态：**已完成（2026-07-29）**。手工 Prompt Get、提示披露、模型工具建议和最终工具执行使用四个互不复用的授权边界；工具结果保持本地不可信且不自动回送模型。

1. Prompt 获取结果先作为不可信内容展示，单独批准后才可进入一次模型调用；手工 `prompts/get` 批准不能复用。
2. 模型只能提出已发现、已固定 schema 的一个工具调用；用户看到精确服务器、工具、参数、数据披露与目的地后一次批准。
3. 工具结果再次作为不可信内容进入独立审查；没有循环自治、隐式重试或 remembered permission。
4. 全链路固定 turn/tool/time/output 预算、取消和追加式审计。

### P4.2 — 远程 MCP Streamable HTTP 与 OAuth

状态：**已完成（2026-07-29）**。远程 capability discovery 和一次明确批准的工具调用已闭环；远程 resource/prompt/model use、Tasks 与后台会话仍保持不可用。

1. 只允许 `https`，解析后和每次重定向都执行 SSRF 防护；禁止回环、私网、链路本地、文件协议和凭证 URL。
2. OAuth 使用 Authorization Code + PKCE、精确 redirect/state 绑定；token 只存系统凭证库，不进入 renderer、日志或仓库。
3. 连接、发现、调用、刷新、撤销和失败均有有界生命周期与内容安全审计。
4. 本地 stdio 与远程 HTTP 共享能力合同，但使用不同传输和凭证适配器。

### P4.3 — 外部提醒目的地

状态：**已完成（2026-07-29）**。首版限定为一个加密 HTTPS Webhook 适配器、固定最小 payload、HMAC、SSRF 防护、最终人工审批、去重和三次有界重试；任意 payload 与连接器市场不在本切片中。

1. 首版只支持一个经过验证的 Webhook 适配器，显式 HTTPS 目的地、一次性测试和系统凭证；不建设连接器市场。
2. 默认只发送任务状态、Artifact 标识和本地打开提示，不发送原始行、路径、问题或模型内容。
3. 每次启用绑定工作流版本与目的地；支持撤销、至多三次退避重试、去重和最终失败证据。
4. 外部发送必须经过人工审批节点；本地通知继续独立可用。

### P5 — 可选 Hub、RBAC、Sync 与集中审计

状态：**已完成仓库内 V1 切片（2026-07-29，剩余项于本轮收口）**。Hub 保持独立可选；同步用户明确选择的端到端加密 workflow definitions，采用四角色双重权限、不变版本、显式冲突决定、删除墓碑、离线重放和 Ed25519 审计。远端工作流现在可在精确摘要审查、本地目标/线程匹配和幂等证据约束下应用；Hub 可选用 PostgreSQL JSONB 持久化，并以表级会话 advisory lock、serializable transaction、行锁和有界重试共同落实跨进程单写者约束。无人值守应用、规范化关系存储和水平吞吐扩展仍不是当前声明。

1. 先定义租户、成员、角色、设备、对象版本、同步包、冲突和审计合同；默认拒绝未知字段与未知权限。
2. 角色保持最小集合：owner、editor、viewer、auditor；服务端和本地出站队列都执行同一权限矩阵。
3. Sync 只同步显式选择的加密产品对象和证据，不默认同步原始行、凭证或本地路径。
4. 使用不可变对象版本、幂等操作 ID 和显式冲突状态；不做静默 last-write-wins。
5. Hub 不可用时本地完整工作；桌面只维护有界 outbox/inbox，恢复后可重放。
6. 集中审计验证签名事件链但不取代本地账本；删除、撤权和设备吊销必须可证明。
7. `services/hub` 只有在合同、服务端、桌面适配、离线测试和端到端旅程同时存在时创建。

## 4. 每个切片的完成合同

每个切片严格按以下顺序：

1. 失败测试和版本化合同；
2. `product-core` 纯策略与性质/边界测试；
3. Go 权威、迁移、事务、取消、预算、审计、备份恢复；
4. main 适配器与一次性审批；
5. renderer 的入口、预览、成功、失败、撤销和恢复；
6. Artifact、重放、合成示例和打包旅程；
7. 当前产品文档、Manifest 与语义验证器；
8. 定向验证后运行根 `npm run verify`。

只有八项同时闭合，Manifest 才能由 `planned` 改为 `implemented`。
