## 1. 最新产品判断

BuBu 当前不是待建设的通用 AI 平台，而是已经形成核心闭环的本地优先周期表格工作台：

```text
导入文件
-> Clean / Merge / Compare / Reconcile
-> 本地分析与证据 Artifact
-> 保存受审周期规则
-> 新文件到达后安全重放或暂停
-> 报告 / Webhook 交付
-> 审计、备份与恢复
```

MCP、RAG、Agent 和 Hub 是渐进增强能力，不能遮挡无模型也可完成的首次任务。新的执行重点从横向扩张改为可信交付、低摩擦上手、生命周期完整和真实市场验证。

## 2. 用户上手路径

### 2.1 三分钟首次价值

首屏以零售示例为首要行动：打开示例、执行一次 Clean、查看影响预览、批准本地执行并打开血缘证据。路径不得要求模型、MCP、Hub 或架构知识。

验收：打包应用在 920 × 640 视口完成成功与取消路径；用户可见文案明确真实数据默认不发送给模型。

### 2.2 十分钟真实任务

按输入结构推荐任务，而不是展示技术模块：

| 输入 | 首选任务 |
| --- | --- |
| 一个文件 | Clean / Analyze |
| 多个同结构周期文件 | Merge |
| 两个业务表 | Compare / Reconcile |
| 每周或每月重复文件 | Repeat |

验收：任务推荐不读取行值、不调用模型、不隐藏其他任务；每个入口均有成功、失败、取消和恢复状态。

### 2.3 下一周期复用

首次结果之后引导保存为受审下期任务、批准本地到达文件夹、查看自动重放、在周期工作中心处理暂停并生成报告。首次成功不能止于一次性导出。

### 2.4 渐进披露高级能力

模型只在自然语言分析时出现；Agent 只在已有受审聚合结果后出现；RAG 只在引用文档时出现；MCP 和 Hub 保持高级设置。显式原始行披露只能由用户主动打开，严格模式永远拒绝远程原始行。

1. 在真实 PostgreSQL 上运行并发单写者、回滚和私有文件迁移集成测试；没有证据时不得把 PostgreSQL 存储写成完全验证。

3. 增加多指标图表切换与本地偏好恢复旅程。
4. 增加报告标题、摘要和组成开关实际改变产物的旅程。
5. 更新 Design QA 与对应截图；视觉证据不替代行为断言。

验收：所有声明为实现的关键适配器没有条件跳过的核心集成场景；三项近期 UI 能力由打包应用真实操作证明。

## 5. P0-C 稳定交付快照

1. 审查大规模工作树，排除生成物、临时文件和无关改动。
2. 运行差异、秘密、依赖、架构、测试、构建、打包和性能验证。
3. 按产品切片形成可审查、可回滚的提交；不创建额外 Git 分支。
4. 只有在用户授权外部发布且真实门禁通过时才推送或发布。

验收：干净检出可复现完整验证；工作树和远端状态明确；不存在只在本机有效的未建账能力。

## 6. P0-D 签名公共 Beta

1. 配置真实 macOS Developer ID、App Store Connect 和 Windows 发布者身份。
2. 生成并人工审查签名、公证的 draft release。
3. 在稳定目标完成干净设备安装、启动、导入、任务、备份、升级、恢复、回滚和卸载。

## 7. P1 产品生命周期

### 7.1 保留与删除

实现用户可见的对话删除、自动保留与轮换、删除前导出/备份提示、原子删除和失败恢复。默认策略必须保守且可关闭；删除不能破坏仍被工作流、Artifact 或审计引用的证据。

### 7.2 配置迁移与恢复

建立版本化、加密或重新授权的配置迁移合同，明确 Agent 定义、隐私策略、提示模板、图表偏好、MCP/Provider 元数据、Webhook 和 Hub 配置的范围。密钥不得进入普通工作区备份；恢复后必须显示需要重新授权的目的地。

### 7.3 自动更新与回滚

签名发布完成后再实现可信更新元数据、包校验、版本兼容、数据迁移、升级失败回滚和降级攻击防护。没有真实签名证据时能力保持不可用。

### 7.4 上手内容产品化

使用轻量首次任务清单、结构驱动任务推荐、首次 Artifact 成功反馈、下一周期引导和高级能力渐进披露；不增加强制全屏教程或仪表盘墙。

## 8. P2 真实用户试点

准备可同意、可撤回、去标识的 5–10 人设计伙伴试点。仓库只实现本地内容安全指标、导出模板和证据检查器，不上传问题、文件名、路径、提示词、模型输出、行值、单元格值或线程身份。

真实验收目标：至少 70% 独立完成首次 Clean/Reconcile；首次 Artifact 中位时间不超过 10 分钟；至少 50% 下一周期返回；至少 80% 暂停任务恢复；至少 60% 成功任务生成报告；零静默语义变化和未批准披露；至少三人接受付费试点或提供等价采购意向。

这些结果只能来自经同意的真实参与者，不能由自动化、合成数据或开发者自测生成。

## 9. P3 由证据触发的扩展

只有 P2 证明具体需求后，才依次考虑工作流 Agent/RAG/MCP 节点、Email/Slack/Teams 交付、OCR/Embedding、自动备份、企业灾难恢复、团队策略分发和 Hub 扩展。每项都必须新建独立能力状态与完成合同。

继续明确排除通用多 Agent swarm、完整 BI/电子表格编辑器、任意 SQL/Python/JavaScript/Shell、原始行默认同步、无人值守远端对象应用和无边界连接器市场。
